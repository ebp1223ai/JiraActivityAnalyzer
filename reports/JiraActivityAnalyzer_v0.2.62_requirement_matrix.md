# Jira Activity Analyzer v0.2.62 Requirement Matrix

| Requirement | Current Production Path | Root Cause / Current Behavior | Planned Change | Verification |
|---|---|---|---|---|
| Changelog vs Activity Events presentation | `IssueViewerPage` renders Changelog from `IssueViewerDto.changelog` through renderer-side `queryLocalTable`; Activity Events invokes `database-viewer:issue-events` and renders `SqliteDataTable` | Changelog is normalized from the compressed Full Fetch payload and only attempts to correlate up to 500 separately loaded activity events. It does not use the Activity Events SQLite query, cache key, paging, or common production table adapter. | Add a server-side SQLite changelog query and mount both tabs through one shared Activity Comparison Table component. | Synthetic schema-v3 fixture compares the same event through Changelog and Activity Events queries and verifies the production route mounts the shared component. |
| Remove Worklogs tab | Static Issue Viewer tab registry, `IssueViewerDto.worklogs`, payload normalization, and tab panel | Viewer always extracts Worklogs while normalizing the Issue payload even when the tab is never opened. | Remove tab, panel, DTO section, and Viewer normalization only. | Route/DTO contract test plus unchanged schema and Full Fetch assertions. |
| Remove Attachments Metadata tab | Static registry, `IssueViewerDto.attachments`, payload normalization, and tab panel | Viewer always extracts attachment metadata while normalizing the Issue payload. | Remove tab, panel, DTO section, and Viewer normalization only. | Route/DTO contract test plus Activity Event attachment fixture remains queryable. |
| Remove Remote Links tab | Static registry, `IssueViewerDto.remoteLinks`, coverage mapping, and shared links panel branch | Viewer evaluates Remote Links coverage and records during every Issue payload normalization. | Remove Viewer tab and normalization path while preserving raw payload and Full Fetch code. | Removed-tab contract test and source-boundary assertions. |
| Legacy active-tab normalization | `IssueViewerSessionState.activeTab` is an unrestricted string and is rendered directly | A restored removed tab produces an empty panel because no validity normalization exists. | Export a valid tab registry and fail-safe normalizer; restore invalid/removed values to `Overview` without clearing other state. | Unit tests for all three removed names, unknown values, and valid tabs. |
| All Users selector scope | User Viewer stores only `selectedUserId`; every IPC requires a non-empty stable user ID | No collision-safe representation exists for a database-wide scope. | Add typed `{ kind: "all" } | { kind: "single-user"; userId }` scope with a separate `none` UI state before selection. | Scope parser/key tests and selector production-wiring assertion. |
| All Users rows/count query parity | User rows/count SQL always starts with `e.actor_account_id = ?` | Removing the predicate is not representable; renderer cannot request all users safely. | Build one validated SQL scope clause used by total count, filtered count, and row query. | Multi-user SQLite fixture verifies counts, rows, filters, sort, and paging. |
| All Users charts/distributions | Distribution issue scope always requires one `userId` | Charts would otherwise retain the prior user or require client aggregation. | Reuse the typed SQL scope for distinct related issues and each distribution dimension. | Fixture verifies distinct issue totals and dimension counts without event over-counting. |
| Scope stale-response protection | Cache keys and pending request checks use the selected user ID | There is no All Users key, and a prior user response could be indistinguishable from a new scope. | Include stable scope key plus database identity in cache keys and keep request-ID fail-closed checks. | Contract test plus renderer state transition assertions for single -> all -> single and database reset. |
