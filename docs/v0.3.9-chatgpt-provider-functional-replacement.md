# v0.3.9 ChatGPT Provider Functional Replacement

## Provider contract

The active providers are `chatgpt_codex`, `ai_nexus`, and `offline_rule`. The
direct OpenAI Platform API provider from v0.3.8 is no longer an active option.
Historical rows that contain legacy provider text remain readable and are not
rewritten.

## ChatGPT runtime

Jira Activity Analyzer pins `@openai/codex` 0.147.0 and packages its Windows x64
runtime under `resources/codex-runtime`. Electron main starts `codex.exe
app-server --stdio`; no global Codex installation, PATH lookup, Python runtime,
local TCP listener, or renderer process spawn is used.

The client follows the official newline-delimited App Server protocol:
`initialize`, account login/read/logout, model and rate-limit reads, ephemeral
thread creation, turn streaming, token usage, interruption, completion, and
thread deletion. See the official [App Server documentation](https://developers.openai.com/codex/app-server)
and [Codex authentication documentation](https://developers.openai.com/codex/auth).

## Authentication and credentials

Browser login is started by App Server. Electron main validates the returned
HTTPS host and opens it externally; the renderer receives only a domain status.
Raw auth URLs, login IDs, thread IDs, turn IDs, tokens, and credential paths are
not exposed through preload.

The runtime uses a dedicated `CODEX_HOME` below `APP_ROOT/app-data`. Its managed
config forces `cli_auth_credentials_store = "keyring"` and
`forced_login_method = "chatgpt"`. If a plaintext `auth.json` exists, startup
fails closed without reading or deleting the file. Jira Activity Analyzer does
not read, copy, log, export, or persist ChatGPT credentials.

## Analysis safety

- Analysis threads are ephemeral, read-only, and use approval policy `never`.
- Command, file-change, permission, dynamic-tool, and user-input server requests
  are declined or rejected by Electron main.
- Jira evidence is explicitly treated as untrusted content, not instructions.
- ChatGPT output uses a constrained schema and allows at most one JSON repair.
- Only completed runs are written to the separate AI Analysis SQLite database.
- Cancelled, failed, partial, interrupted, and unknown-outcome runs are not
  persisted or exported as completed results.

## ENV v4

`.env.version` now uses `ENV_FORMAT_VERSION=4`. ChatGPT has no `.env` key. AI
Nexus retains endpoint, model, contract, token, timeout, and retry settings under
the `AI_NEXUS_*` namespace. Deprecated `AI_CLOUD_*`, `OPENAI_API_KEY`, and
`AI_API_KEY` keys are ignored and reported only as a key-name warning; values
are never logged.

## Verification boundary

Automated tests use a deterministic fake App Server process for JSONL
fragmentation, malformed input isolation, timeout, managed login, account/model/
quota hydration, tool rejection, streaming, token usage, cancellation, clean
completion, and runtime crash behavior. Real ChatGPT OAuth, plan quota, and Jira
analysis remain manual validation items because no real account credentials are
used in automated tests.
