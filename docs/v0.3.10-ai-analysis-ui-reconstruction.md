## Manifest-only rules loader

The selected directory must contain exactly one canonical Manifest. Only the
Catalog and Common Rules paths bound by that Manifest are loaded. The loader:

- resolves canonical Windows paths with `realpath`;
- rejects references outside the selected root;
- rejects duplicate canonical file identities;
- does not recursively scan or append prior selections;
- records full path, version, size, mtime, and SHA-256 for all three files;
- detects exact, trimmed, Unicode-normalized, and case-insensitive Skill ID
  collisions with source path, line number, record index, and load source.

The supplied 279-record Catalog was validated as 279 records, 279 unique Skill
IDs, and zero duplicate Skill IDs. This is a measured result, not a hard-coded
success condition.

## Full-path contract

Electron main owns all file and directory dialogs. Renderer snapshots retain
the actual absolute path for the rules directory and bound files, Pending JSON,
Analyzed JSON, planned/final output JSON, diagnostics, reports, and the separate
AI Analysis SQLite database. Long values wrap visually while the DOM, title,
copy action, IPC value, and persisted metadata retain the complete path.

Renderer code cannot nominate an arbitrary rules path during revalidation. A
reload uses only the previously user-selected path or the explicit environment
configuration.

## Run state machine and persistence

Run states remain `queued`, `running`, `retrying`, `cancelling`, `cancelled`,
`completed`, `partial`, `failed`, and `interrupted`. Before a run, Electron main
re-reads and locks the rules snapshot and Pending Dataset, verifies their hashes,
checks the selected provider, and verifies that the separate SQLite database can
be initialized.

Progress comes from actual per-Diff work and provider events. ChatGPT and AI
Nexus token usage is aggregated only when providers return it; Offline Rule
Analyzer token usage is zero/not-applicable. Cancellation aborts the active
provider request and prevents completed persistence.

The final JSON uses an atomic create, fsync, close, rename, and read-back digest
check. Only a completed, count-conserving run can be written to the final JSON
and AI Analysis SQLite. A database failure removes the final JSON and reports a
failed run. Cancelled, failed, partial, interrupted, timeout, and unknown-outcome
runs do not enter the completed results list.

## Provider and data boundaries

- Active providers remain `chatgpt_codex`, `ai_nexus`, and `offline_rule`.
- ChatGPT uses bundled Codex App Server 0.147.0, keyring-only login, ephemeral
  read-only threads, and rejects shell, file, permission, MCP, plugin, skill,
  and dynamic-tool requests.
- AI Nexus keeps the ENV v4 `AI_NEXUS_*` contract. Renderer receives masked
  secret state and never reads the token.
- Offline Rule Analyzer is deterministic and network-free.
- Jira evidence is passed only from the selected Pending Dataset. Providers do
  not scan SQLite, APP_ROOT, user directories, or the rules folder.
- Manual chat writes sanitized request and response traces. Authorization and
  token values are always masked.
