# v0.2.41 Stable Hash V3, Coverage, and Event Identity V2

## Database generation

v0.2.41 creates Current-State schema version 2 databases with:

- `storage_model = current_state`
- `storage_model_version = 1`
- `stable_hash_policy_version = 3`
- `event_identity_policy_version = 2`

v0.2.39 history databases and v0.2.40 Current-State V2 databases are inspected read-only. The application does not migrate, repair, compact, copy, or rewrite them.

## Stable Hash V3

The first eligible Stage 5 save resolves configured volatile display names against authoritative Jira `names` metadata. The resulting effective policy is canonicalized, fingerprinted, and frozen atomically with that Issue transaction.

Exact fixed exclusions include acquisition metadata, `fields.updated`, and `fields.lastViewed`. Only verified Field IDs are excluded for volatile calculated fields. Unresolved or ambiguous fields remain part of stable business content.

Nested business timestamps such as Comment `updated` remain meaningful. Coverage is compared separately from business content, so an authoritative Coverage upgrade can replace the archive without incrementing `content_revision`.

## Current Observed Metrics

`current_observed_metrics` stores one latest row per Issue and resolved volatile Field ID. Rows preserve type, missing versus explicit null, observation time, and run provenance. Stable-equal saves may update these rows while intentionally retaining the older large Payload.

## Coverage evidence

Every dimension records status, item count, source, request completion, validation result, and reason code. Issue Links are valid only when `issue.fields.issuelinks` is an array and its validated count agrees with evidence.

Issue Links, Remote Links, and Related Issues Discovery are independent. Disabled, Skipped, Failed, Partial, CompleteEmpty, and CompleteNonEmpty are not interchangeable.

## Event Identity V2

- Comment Created: `comment_created:<commentId>`
- Comment Updated: `comment_updated:<commentId>:<normalizedUpdatedTimestamp>`
- Changelog event: `jira_changelog:<historyId>:<itemIndex>:<normalizedFieldIdentity>`
- Attachment Added: `attachment_added:<attachmentId>`

Current Issue Link snapshots never generate activity events. Link events require a Jira changelog history item. Missing Jira-native identity skips the event and emits a safe warning.

## Transaction behavior

Snapshot, Payload, Sync State, Current Observed Metrics, and new Activity Events share one per-Issue SQLite transaction. Partial, failed, invalid Coverage, policy mismatch, server mismatch, or transaction failure retains all prior formal state.

Stage 5 diagnostics contain only safe paths, IDs, counts, policy fingerprints, Coverage evidence, event counts, and reason codes. They do not include credentials, full payloads, full descriptions, or full comment bodies.
