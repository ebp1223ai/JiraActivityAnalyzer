# AI Analysis v0.3.8 Architecture

## Trust boundaries

The renderer uses the versioned `window.desktopApp.aiAnalysis` IPC facade. It never reads the environment, filesystem, SQLite database, or HTTP endpoints directly. API keys and bearer tokens are loaded and used only by Electron main-process code. Public configuration contains a boolean and mask, never the secret value.

## Versioned contracts

- IPC contract: `AI_ANALYSIS_IPC_VERSION=1`
- Input contract: `ai-analysis-input-v1`, backed by the existing `jira-activity-analyzer.pending-analysis` compact schema
- Output contract: `ai-analysis-output-v1`; analyzed file schema `0.3.8-v1`
- AI Analysis SQLite schema: version 1
- Environment format: `ENV_FORMAT_VERSION=3`

## Provider behavior

The provider layer supports Responses and Chat Completions wire contracts. Requests run in the main process with bounded timeout, bounded retries for transport/408/429/5xx failures, `Retry-After` support, exponential backoff, cancellation, nullable normalized token usage, and sanitized response metadata. OpenAI Responses requests set `store: false`.

Live cloud and internal-provider validation is intentionally not performed by automated tests. Tests use a loopback HTTP server and synthetic evidence.

## Rules and input

The rules loader requires a manifest, Skill Catalog, and Common Rules file. It checks the selected directory and real paths, rejects symlink escape and duplicate skill IDs, computes SHA-256 digests, and freezes the parsed snapshot into every run.

Pending-analysis input is bounded to 64 MiB and must pass the existing schema, count, digest, source identity, compact-content, and credential/path integrity checks. Only explicitly selected stable diff IDs enter a run.

## Persistence and review

AI output is stored in a separate writable SQLite database. Jira and Current-State databases remain read-only. Schema v1 keeps source datasets, rule snapshots, immutable run revisions, run items, attempts, candidates, raw results, review audit records, exports, and diagnostics. Partial or failed runs cannot be persisted as completed output.

Candidates default to `PENDING_REVIEW`; only a user review action can set `CONFIRMED` or `REJECTED`. Review changes append an audit row and update the stored run projection.

## Export

Completed runs can be exported from the main process as versioned JSON, UTF-8 BOM CSV, or self-contained HTML. Writes use a same-directory temporary file, atomic rename, reopen, and SHA-256 verification. HTML uses local styles and escapes all dynamic text; it has no CDN or remote dependency.
