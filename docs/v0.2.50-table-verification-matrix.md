## Contract Notes

- Activity Event presentation IDs map explicitly to backend fields: `displayName -> actor`, `eventType -> action`, `fieldName -> field`, `sourceProvenance -> source`.
- Filters on different fields use SQL `AND`. Values inside one multi-select field use SQL `OR`.
- Unsupported fields fail before SQL execution with `FILTER_UNSUPPORTED_FIELD:<field>`.
- Count and rows use the same generated `WHERE` clause. Stable pagination adds an event or Issue identity tie-breaker.
- Preference v2 stores independent table visibility, order, widths, page size/index, sort and bounded filters. Corrupt, null, unknown and legacy values normalize before renderer use.
- Activity Event Before/After come from persisted schema-v2 values. No adjacent-event inference or schema migration is used.
