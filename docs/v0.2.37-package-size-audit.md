# v0.2.37 Windows Package Size Audit

## 方法與口徑

先以尚未修改 dependency 分類、ASAR、壓縮或排除規則的 v0.2.37 產生 baseline，再執行 `node scripts/audit-package-size.cjs before ...`。最佳化後重新建立 Installer、Portable 與 `win-unpacked`，以相同腳本與口徑產生 after audit。

腳本遞迴計算實體目錄，並使用 `@electron/asar` 讀取 ASAR header 取得虛擬檔案大小。`packagedNodeModules` 是 ASAR 內非-unpacked `node_modules` 加上 `app.asar.unpacked/node_modules`。前 50 大檔案同時顯示 package 實體檔案與 ASAR 內檔案，因此 `app.asar` 容器與其內容是不同觀察口徑，不可相加當成實際 package 總量。

ASAR 最佳化前與最佳化後都啟用；最佳化後明確設定 `asar: true`。Baseline 的實際 unpack 範圍是建置工具原生 binary；after 沒有 `app.asar.unpacked`。

採用：

- 將 `@vitejs/plugin-react`、`typescript`、`vite` 從 production dependencies 移至 devDependencies。Audit 證明 TypeScript、Vite、Babel、esbuild 與 Rollup binary 被誤包，但正式執行碼已由 Vite/esbuild bundle。
- 明確設定 ASAR 與 electron-builder `maximum` compression。
- 排除 `node_modules/**/*.map`；source map 不參與執行。

未採用：

- 不排除 Electron、Chromium、Node、DLL、locale、gzip 或內建 SQLite；它們是必要基礎容量。
- 不使用 UPX。
- 不移除 production dependency 的 runtime files；renderer 雖已 bundle，保留它們是較保守的正式依賴策略。
- After 仍辨識到 0.472 MiB dependency docs 等非執行內容；容量極小，為避免套件特定排除造成升版風險，本版不再追求數字。
- 未加入 locale 白名單；現有產品未定義支援語言收斂政策，任意移除可能破壞其他語系。

最佳化後 `win-unpacked` 的主要分類：Electron Required Runtime 283.839 MiB、Static Asset 53.749 MiB、Application Code 44.875 MiB、Production Dependency 20.279 MiB、Test／Development Artifact 0.472 MiB。Electron 主執行檔 224.787 MiB、Chromium DLL／資料與 locales 是不可安全移除的主要基礎容量。

Installer 與 Portable 由同一個 `app.asar` 與 Electron runtime 建立，未發現額外的第二份 application bundle。兩者是各自獨立的發行格式，不把兩個輸出檔同時放進彼此。

## 驗證

最佳化後重新執行 Unit、Integration、Regression、Production Build、Windows Packaging、`win-unpacked` packaged smoke 與 Portable packaged smoke。兩種封裝都通過離線 UI／IPC／資料庫測試；Portable 的 `.env`、logs、temp 與測試 SQLite 均位於執行檔旁。ASAR 清單不含 `.env` 或 `.env.Version`，Installer／Portable 建立前的 `win-unpacked` 也沒有 runtime `.env`。
