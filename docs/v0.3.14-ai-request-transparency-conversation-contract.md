# v0.3.14 AI Request Transparency and Durable Conversation

## Scope

v0.3.14 makes each ChatGPT analysis auditable from immutable input bytes through formal persistence. It preserves one Provider dispatch, one ephemeral thread, one turn, no automatic retry/repair/fallback, warn-only capacity confirmation, and completed-only JSON/Golden HTML/SQLite writes.

## Request Package

Each accepted ChatGPT run creates `<APP_ROOT>/app-data/ai-analysis/runs/YYYY/MM/DD/<local-time-ms>_<runId>/request-package/` before crossing the Provider boundary. The package contains one original Pending Analysis JSON, three original Markdown rule documents, a versioned immutable core instruction plus optional supplemental instruction, and the exact Strict Output Schema.

The current Provider delivery mode is `INLINE_EXACT_CONTENT`. Five model-visible blocks preserve complete UTF-8 source bytes, filename, role, ordering, byte count, SHA-256, and deterministic boundaries. The schema is sent through the App Server output-schema channel. Native attachments are not claimed. Any changed source hash, record-count mismatch, Stable ID mismatch, incomplete block, truncation, or final payload hash mismatch fails before `thread/start`.

## Durable Run Archive

`conversation.jsonl` is append-only canonical evidence. Every event records run/event identity, monotonic sequence, local and UTC timestamps, role, visibility, content bytes/SHA-256, Provider correlation, previous hash, and event hash. Writes loop until complete and `fsync` before returning. `provider-stream.jsonl` stores ordered sanitized Provider envelopes with payload bytes/SHA-256. `conversation.md` is a deterministic readable derivative.

On restart, terminal runs remain available and active non-terminal runs become `Interrupted`; no Provider request is replayed. A partial conversation tail is retained as recovery evidence before the canonical JSONL is truncated to its last complete line. Historical conversation is read in bounded pages. Only a terminal Run can be manually deleted after confirmation.

## Canonical Response Contract

Schema version `ai-analysis-output-v3` supports record statuses `MATCHED`, `EXCLUDED`, `UNKNOWN`, `CATALOG_DETAIL_MISSING`, and `NEEDS_REVIEW`. Candidates support all except `UNKNOWN`, and preserve `candidateStatus`, `statusReason`, and `catalogDetailAvailable`.

- `MATCHED`: candidate and positive evidence required; record/candidate negative checks may be empty.
- `EXCLUDED`: no record candidates, non-empty exclusion reason, and auditable record negative checks.
- `UNKNOWN`: no candidates, non-empty unknown reason, and auditable missing-evidence checks.
- `CATALOG_DETAIL_MISSING`: candidate retained, `catalogDetailAvailable=false`, positive evidence retained, failed Catalog-detail check, and review attention required.
- `NEEDS_REVIEW`: non-empty review reason and an evidence/check audit trail.

Validation runs in this order: full raw response assembly and hash verification, JSON parse, Strict Schema, identity/Catalog/evidence ownership, status-aware semantics, artifact preflight, and SQLite transaction. Findings include JSONPath, JSON Pointer, record/Stable ID, candidate index, Skill ID, expected, actual, and rule ID. Provider-returned, parsed, schema-valid, semantic-valid, formal-artifact, and SQLite counts remain separate.

## Response Evidence and Security

The Run archive retains full `provider-stream.jsonl`, `provider-response.raw.json`, verified gzip response, `provider-response.canonical.json`, semantic findings, manifests, and hashes. Debug copies verify their uncompressed SHA-256 against the Run manifest. The old 8,192-character helper remains UI/log preview-only; canonical writers use complete deterministic redaction without slicing.

Credentials, Authorization, cookies, auth state, `.env`, Jira/AI tokens, real Pending data, rule documents, databases, response evidence, and Run archives remain local under APP_ROOT and are excluded from Git/release source artifacts. ENV format remains v4.
