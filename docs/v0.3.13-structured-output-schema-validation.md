# v0.3.13 Structured Output Schema Validation

## Canonical contract

`electron/aiAnalysisOutputSchemaV0313.ts` is the single Provider wire-schema source. `scoreComponents` is an array of fixed objects:

```ts
type ScoreComponent = {
  componentKey: string;
  score: number;
  explanation: string | null;
};
```

The canonical analyzed run stores this array. Explicit deterministic adapters exist only for reading a legacy display map; duplicate component keys fail closed.

## Strict preflight

Before model-capacity lookup or Provider dispatch, Electron main:

1. Builds the exact output schema.
2. Canonicalizes object keys and creates UTF-8 bytes.
3. Calculates SHA-256 and deep-freezes the parsed canonical object.
4. Recursively validates required/properties equality, `additionalProperties: false`, arrays, `anyOf`, local references, supported keywords, and current size limits.
5. Persists the sanitized schema, canonical bytes, validation result, and hash.
6. Sends the same frozen object and verifies its hash again at the Provider boundary.

The limits follow the current [OpenAI Structured Outputs documentation](https://developers.openai.com/api/docs/guides/structured-outputs): 10 nesting levels, 5,000 object properties, 1,000 enum values, and 120,000 schema string characters. A local failure creates no Provider dispatch, thread, or turn.

## Runtime gates

The completed-only pipeline is:

```text
provider completed
-> response JSON parsed
-> canonical schema validated
-> record identity conserved
-> Catalog and evidence validated
-> formal JSON and Golden HTML written
-> SQLite transaction committed
```

Failures preserve staging evidence and never retry, repair, fall back, or partially write formal data.

## Counters and diagnostics

Runs separately record Provider dispatch, thread start attempt, thread creation, turn start attempt, accepted turn, completed turn, retry, repair, and fallback counts. Debug evidence uses the same output-schema SHA-256 as the outgoing request.

The prior repeated renderer error was caused by a newly-created `appendDebugLog` callback on each `AppLayout` render. It retriggered the terminal notice effect after every log-state update. The callback is now stable through `useCallback`; persistent error dedup also includes a normalized root-cause hash.
