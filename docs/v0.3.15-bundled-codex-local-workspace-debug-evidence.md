# v0.3.15 Bundled Codex Local Workspace and Canonical Evidence

Jira Activity Analyzer packages the official Apache-2.0 OpenAI Codex 0.147.0 Windows x64 runtime as an unpacked Electron resource. Build creates `codex-runtime-manifest.json`; startup verifies version, platform, relative executable path, and SHA-256 before App Server can start. No PATH discovery, external fallback, or runtime download exists.

ChatGPT sign-in is initiated through the bundled App Server managed OAuth flow. JAA never parses or copies the OAuth token. Conversation history belongs to the local JAA Canonical Run and is not synchronized to ChatGPT web conversations.

Each analysis creates `<APP_ROOT>/exports/ai-analysis/runs/YYYY/MM/DD/<local-time>_analysis_<uuid>/`. `input-workspace/` contains exactly one byte-identical Pending JSON and three Markdown rule files. The single short turn instruction tells Codex to read those files; file contents are never expanded into the provider text and there is no inline fallback, Files API upload, software batch, or repair turn.

The output schema is generated with `minItems` and `maxItems` equal to the actual input count. JSON parse, strict schema, count, identity, source hash, ordering, Catalog Skill ID, semantic, formal artifact, and SQLite gates remain fail closed. Failed, cancelled, interrupted, or partial results never enter the formal AI Analysis database or Golden HTML.

`conversation.jsonl` and `provider-stream.jsonl` are append-only and fsynced. The run manifest, input snapshots, control files, response evidence, validation, runtime diagnostics, token usage, and execution time share the same Canonical Run. Debug Folder copies the selected Canonical Run, verifies source/destination SHA-256, and writes `debug-completeness-manifest.json`; missing required evidence, failed flush state, or hash mismatch produces `incomplete` rather than a false completion.

Manual validation still requires an interactive ChatGPT account and a real selected dataset. Automated tests do not spend cloud quota.
