# v0.3.12 Capacity Override and Diagnostics

v0.3.12 replaces the v0.3.11 model-capacity hard block with a traceable,
warn-only confirmation flow. It does not split the selected records, retry a
failed turn, or create a repair/fallback request.

## Capacity evidence

The main process requests the exact selected provider/model capability from
Codex App Server first. Exact provider model metadata is used only when its
field semantics are known. Missing or unsupported capability data remains
`unavailable`; it is never converted to zero or a fixed 200,000-token limit.

One `CapacityCalculationSnapshot` is shared by the UI, run manifest, failed
staging, debug evidence, and release ledger. The current fallback estimator is
`ceil(final serialized prompt UTF-8 bytes / 3)`. Output reserve is
`max(8,192, recordCount * 640)`. Safety margin remains 8% of known capacity;
when capacity is unavailable, 8% of estimated input is used and identified as
an estimator fallback so the required-total estimate remains visible.

Unknown capacity and known overage are warnings. The confirmation dialog shows
all bytes, token estimates, reserve terms, formulas, source status, margin, and
overage. Cancel creates no request, thread, or turn. Confirmation atomically
permits one dispatch for the existing `analysisRunId`.

## Persistence gates

Formal JSON, Golden HTML, and AI Analysis SQLite are opened only after a
completed provider turn, saved visible response, valid JSON, exact input/output
identity conservation, and exact Catalog validation. Incomplete, invalid,
cancelled, or failed runs are not repaired or retried.

Failed ChatGPT runs are permanently retained at
`<APP_ROOT>/exports/ai-analysis/failed-staging/<analysisRunId>/`. Each directory
is created exclusively and is never overwritten or automatically deleted. The
existing Debug Folder collector copies the latest sanitized failed-run evidence
under `ai-analysis/` without moving the source.

## Verification

Synthetic targeted tests cover capacity availability, overage, unavailable
capacity, the v0.3.11 calculation fixture, one-shot dispatch, cancellation,
error deduplication, persistence gates, APP_ROOT containment, collision safety,
and sanitized failed evidence. These tests do not represent a live provider
run. The real 117-record result remains a separate final Release Portable
validation and must be reported as unavailable or Partial if authentication or
interactive execution is unavailable.
