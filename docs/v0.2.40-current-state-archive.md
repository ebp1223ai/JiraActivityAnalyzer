# v0.2.40 Current-State Archive

## Storage Model

The v0.2.40 writable database is a new SQLite file with:

- `storage_model = current_state`
- `storage_model_version = 1`
- `stable_hash_policy_version = 2`

Formal tables are `database_metadata`, `source_objects`, `current_issue_snapshots`,
`current_full_fetch_payloads`, `issue_sync_states`, `activity_events`, and
`database_run_state`. Legacy `source_object_versions`, history `source_payloads`,
and `source_import_refs` tables are neither created nor used.

Every Jira Issue has at most one Snapshot, one compressed Full Fetch Payload, and
one Sync State. Activity Events remain append-only and are deduplicated by
`(source_object_id, event_identity_hash)`.

## Stable Projection V2

Stable Projection includes authoritative business fields, complete comments and
changelog, attachment metadata, issue relationships, and explicit Coverage
markers. Runtime timestamps, queue/evidence paths, `names`, `schema`,
`renderedFields`, and Jira `updated` alone do not participate.

Known live-calculated fields are resolved from Jira `names` metadata to exact
Field IDs. A missing mapping emits a non-fatal warning. An ambiguous display
name excludes no fields and emits `AMBIGUOUS_VOLATILE_FIELD_MAPPING`.

Java `Object.toString` hexadecimal identity suffixes are normalized narrowly;
the meaningful Development value remains part of the stable hash.

## Coverage Gate

Each section is one of `Disabled`, `Skipped`, `Failed`, `Partial`,
`CompleteEmpty`, or `CompleteNonEmpty`. Comparison returns `Equivalent`,
`Upgrade`, `Downgrade`, `Incomparable`, or `Invalid`.

Only Equivalent or Upgrade candidates may be saved. Downgrade, Incomparable,
Partial, Failed, and conservation failures leave all formal per-Issue rows
unchanged.

## Transaction and Payload Safety

Before a transaction, the candidate JSON is deterministically serialized,
hashed as exact UTF-8 bytes, compressed, decompressed, re-hashed, and parsed.
Snapshot, Payload, Sync State, and Activity Events then commit in one Issue
transaction. Fault-injection tests prove rollback after Snapshot update and
during Activity Event insertion.

Stable-equal content with equivalent Coverage updates successful-check metadata
and event deduplication only. It does not rewrite the Snapshot, Payload BLOB,
`payload_updated_at`, or `content_revision`.

## Legacy Databases

v0.2.39 databases are opened only for detection. They are not migrated,
renamed, compacted, deleted, or activated as a writable Current-State database.
A separate v0.2.40 database must be created while connected to the intended Jira
Server Identity.

## Manual Acceptance

This procedure requires a new v0.2.40 database and a safe company Jira test
environment. It is not executed by automated fixture tests.

1. Full Fetch four fixed Issues and save Stage 5: expect 4 New and 4 Payloads.
2. Fetch the same four again: expect 4 Existing and zero Payload replacements.
3. Change one real Jira Label: expect 1 Updated and 3 Existing.
4. Fetch again: expect 4 Existing.
5. Change only a confirmed volatile calculated field: expect 4 Existing.
6. Simulate one Partial result: expect one Excluded and unchanged prior state.
7. Inject one Issue transaction failure: expect that Issue to roll back fully.

Verify with:

```sql
SELECT COUNT(*) FROM source_objects;
SELECT COUNT(*) FROM current_issue_snapshots;
SELECT COUNT(*) FROM current_full_fetch_payloads;
SELECT COUNT(*) FROM issue_sync_states;

SELECT source_object_id, COUNT(*) FROM current_issue_snapshots
GROUP BY source_object_id HAVING COUNT(*) > 1;

SELECT source_object_id, COUNT(*) FROM current_full_fetch_payloads
GROUP BY source_object_id HAVING COUNT(*) > 1;

SELECT source_object_id, event_identity_hash, COUNT(*) FROM activity_events
GROUP BY source_object_id, event_identity_hash HAVING COUNT(*) > 1;

PRAGMA integrity_check;
PRAGMA foreign_key_check;
```

Also compare `content_revision`, `successful_fetch_count`,
`payload_updated_at`, total Payload rows/BLOB bytes, the old database SHA-256,
and the `.env` database path before and after explicit activation.
