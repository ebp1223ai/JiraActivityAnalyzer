# v0.2.37 啟動設定與本機資料庫就緒

## 設定來源

- `.env` 是唯一執行階段設定來源，可能包含本機 credential，因此不得提交。
- `.env.Version` 是可提交、無 credential 的雙語格式範本，執行階段明確拒絕載入。
- 目前格式為 `ENV_FORMAT_VERSION=2`。舊 `.env` 缺少新欄位時使用安全預設值，既有 alias 仍可讀取。
- UI 更新 `.env` 時只替換指定鍵，保留註解、未知鍵、換行格式與其他值；寫入採同目錄暫存檔、flush、atomic rename，失敗時保留原檔。
- Jira 設定流程為「測試 → 成功 → atomic patch → 重跑全域狀態」。測試失敗只顯示實際結果，不修改 `.env`。
- Database 路徑只有在完整 compatibility check 成功後才保存。

## 路徑與 Portable

`LOCAL_DATABASE_PATH` 的相對路徑一律以 `APP_ROOT` 解析；絕對路徑可指向外接或其他本機位置。位於 `APP_ROOT` 內的路徑保存時會轉成相對路徑，外部路徑維持絕對路徑。中文與空白路徑均由 Node path API 處理。

正式封裝的 `APP_ROOT` 是執行檔所在目錄；開發與測試則使用明確指定的 root。Portable 不以 `%LOCALAPPDATA%` 作為 fallback；root 不可寫時會清楚失敗，不會靜默改用其他位置。

## 啟動與 Runtime State

Jira 與 Database 檢查在 UI 建立後平行執行，不阻擋 renderer。兩條檢查各有單調遞增 request ID，較舊回應不會覆蓋較新的 Retry 結果。所有主要頁面共用同一份 Runtime State。

Jira 狀態：

`CHECKING`、`CONNECTED`、`NOT_CONFIGURED`、`INVALID_URL`、`DNS_ERROR`、`NETWORK_ERROR`、`TIMEOUT`、`TLS_ERROR`、`AUTH_FAILED`、`PERMISSION_DENIED`、`SERVER_ERROR`、`UNSUPPORTED_RESPONSE`、`UNKNOWN_ERROR`。

Jira 檢查只送出 read-only GET，timeout 為 10 秒；network 與 5xx 最多重試一次，401／403 不重試。成功時記錄 normalized base URL、account、latency、最後測試／成功時間，以及 server ID 或穩定 SHA-256 fallback identity。Token 永不進入狀態、log 或錯誤內容。

Database 狀態：

`CHECKING`、`READY`、`READY_READ_ONLY`、`NOT_CONFIGURED`、`MISSING`、`INVALID_SQLITE`、`FOREIGN_DATABASE`、`SCHEMA_INCOMPLETE`、`MIGRATION_REQUIRED`、`TOO_NEW`、`JIRA_INSTANCE_MISMATCH`、`CORRUPTED`、`LOCKED`、`PERMISSION_DENIED`、`UNKNOWN_ERROR`。

Compatibility check 依序驗證：

1. 檔案存在、是一般檔案且可讀。
2. SQLite header、read-only open、`PRAGMA quick_check`。
3. 七張表、FK／Index、產品識別、database type、schema version。
4. Jira source binding；mismatch 可唯讀，但禁止 import。

`MIGRATION_REQUIRED` 在本版只提示，不會自動 migration、repair、copy、backup、binding rewrite 或 import。

## Capability 規則

- Jira Connected：開放 Jira 搜尋、Candidate Discovery、Full Fetch Staging。
- Database `READY`／`READY_READ_ONLY`／`JIRA_INSTANCE_MISMATCH`：開放 database read 與 offline analysis。
- 正式 database import 只在 Jira Connected 且 Database `READY` 且 binding 不 mismatch 時開放。
- Jira 失敗不封鎖有效 Local Database；Database 失敗不封鎖已連線 Jira 的搜尋與 staging。

## Source Archive Schema

Schema version 為 `1`，product ID 為 `jira_activity_analyzer`，database type 為 `source_archive`。

| Table | 主鍵與主要約束 | 關聯／用途 |
|---|---|---|
| `database_metadata` | `database_id` PK／UNIQUE、單一產品與 schema metadata | Source Archive 身分 |
| `schema_migrations` | migration ID PK、version | FK → metadata，記錄建庫 schema |
| `source_system_bindings` | binding ID PK；UNIQUE(database, source system) | FK → metadata，保存 Jira server identity |
| `source_objects` | object ID PK；UNIQUE(source system, type, key) | Jira／Confluence 來源物件 |
| `source_object_versions` | version ID PK；UNIQUE(object, content hash) | FK → object；相同內容去重、不同內容保留歷史 |
| `source_payloads` | payload ID PK；version ID UNIQUE | FK → version；canonical JSON gzip blob、SHA-256、原始大小 |
| `source_import_refs` | import ref ID PK；複合 UNIQUE | FK → version；來源 bundle/file/JSON path 追溯 |

所有必要 FK 都使用 `ON DELETE CASCADE`。索引涵蓋 migration/database、binding identity、object last-seen、version object/last-seen、source update time，以及 import bundle/file。

Archive API 將原始 JSON 正規化為穩定 key order，排除 exporter 自行加入的執行時間、bundle、檔名與 JSON path 等不穩定欄位，再計算 SHA-256 並 gzip。相同物件與相同 content hash 更新 `last_seen_at`，不新增 snapshot；內容不同會建立新 version 並保留舊 version。Jira `source_version_number` 可以是 `NULL`。

Full Fetch fixture 與 Issue Snapshot 可透過 service API 保存，但本版沒有自行發明自動 import UI，也不保存 Activity Stream、Full Fetch Run History、Queue、Retry、分析結果、附件 binary 或 Jira／Confluence link 正式關聯表。

## UI 與 IPC

AppLayout 內的全域狀態列在所有主要頁面顯示 Jira／Database 狀態、原因、路徑／identity、最後檢查時間與 Retry。Connections 頁提供 Select Existing、Create New 與 capability 摘要。

Preload 只暴露窄化 IPC：

- `runtime.getState/retryJira/retryDatabase/onStateChanged`
- `connections.testAndSave`
- `databases.checkPath/selectExisting/createNew`

Renderer 不直接存取 Node、檔案系統或 SQLite。

## 安全邊界與已知限制

- 本版所有驗證使用 mock、fixture 與 temporary SQLite，沒有連線真實 Jira／Confluence。
- Compatibility check 以 read-only SQLite 開啟；只有明確 Create New 或 repository store API 會寫入。
- Source Archive repository API 尚未接到現有 Full Fetch 自動流程或手動 Import UI。
- 本版不提供 migration、repair、binding 修改、source object 刪除 UI、Full Fetch run history 保存或自動 import。
- `node:sqlite` 由 Electron／Node runtime 提供，不依賴外部 SQLite 安裝或第三方 native addon。
